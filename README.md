# 牛顿顿顿 · 千问办公协作项目

项目创建者与 Awei 使用各自的 agent 准备测试材料、记录实测，并由创建者的 agent 汇总最终方案。公司、人物及业务数据均为虚构。

当前采用用户确认的仓库版本 [`d8c2381`](https://github.com/addsoleil/Qwen/commit/d8c2381f749368ebae71b0f868a0b110b569f52d)：烘焙连锁、6 个角色、4 个钉钉群、11 个测试任务。此次仅重建协作结构，不使用外部 Artifact 替换仓库方案。

## 开工先读

1. [AGENTS.md](AGENTS.md)：共同协作规则。
2. [公共资料/测试方案.md](公共资料/测试方案.md)：当前业务方案，测试编号、角色、商品、日期均以此为准。
3. [创建者/交接.md](创建者/交接.md) 与 [Awei/交接.md](Awei/交接.md)：双方当前分工、完成内容及问题。

## 双方分工

| 协作者 | 默认职责 | 具体业务任务 |
| --- | --- | --- |
| 创建者（仓库所有者） | 维护公共方案；汇总双方交付并更新最终方案 | 由创建者在自己的交接中确认 |
| Awei | 在自己的工作区制作材料、记录测试、整理素材 | 由 Awei 在自己的交接中确认 |

业务任务尚未分配时，不按虚构角色或 GitHub 提交者猜测负责人。仓库工作区属于真实协作者；方案内的角色属于测试表演，两者不自动对应。

## 怎么协作

1. 先同步最新 `main`，阅读公共方案和双方交接，明确本次负责的内容。
2. 各自使用个人分支，只修改自己的工作区；需要修改公共资料时在交接中提出。
3. 文件沿用当前方案的任务编号，例如 `T05-自动调货.md`；编号或名称变化时跟随当前方案，不另编一套台账。
4. 完成一批内容后更新交接的“已完成，可汇总”，提交 PR，由创建者合并。
5. 创建者的 agent 读取双方交接中的可汇总项，核对原文件后更新 `最终方案/`，在采用位置保留来源路径与提交版本。

## 材料与结果

- 公共初始材料保持初始状态，实测后的表格、文档另存个人 `测试记录/` 或 `材料/`。
- 预期结果与实测结果分开；没有执行的任务写“未测”。实际结果需要指向截图、录屏或原始输出。
- 给被测产品导入业务材料时，不把包含预期答案、埋点和双方交接的整个仓库上传。
- `最终方案/` 初始化时只有汇总说明，不代表测试已经完成。

不建立任务台账、JSON 清单、自动轮询或复杂验收流程；双方通过各自的 `交接.md` 交接。
